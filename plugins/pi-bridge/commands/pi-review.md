请 pi 评审当前仓库的改动，然后逐条核实。

1. 用 Bash 的 `run_in_background` 在后台执行下面的命令，告诉用户评审已在后台进行，然后结束当前回合：

   ```bash
   pi-bridge review $ARGUMENTS
   ```

   评审范围：不加参数时为工作区相对 HEAD 的全部改动（含未跟踪文件）；`--staged` 只看已暂存的改动；`--base <分支>` 看相对该分支分叉点的全部改动。

   收到后台任务结束的通知后，用 Read 读取它的输出文件。输出为“没有可评审的改动”时，直接告诉用户并结束；退出码非 0 时，把 `pi-bridge:` 开头的错误原因告诉用户并结束。

2. 对 pi 提出的每一条问题，打开对应代码核实，标注：
   - **认同**：问题确实存在，说明依据（引用 `文件:行号`）；
   - **不认同**：问题不成立或不适用，说明理由；
   - **待确认**：需要用户掌握的背景才能判断，说明缺什么信息。

   某一条看不懂或需要 pi 补充依据时，用回复末尾给出的评审会话名追问：`pi-bridge send <评审会话名> <消息>`，同样在后台执行。

3. 按严重程度从高到低，用表格呈现：序号、pi 的结论、核实结果、理由、建议的改法。

4. 不要自动修改代码。呈现完后询问用户要处理哪些条目。
